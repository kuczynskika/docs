# How to create, edit, and delete Relays

Every Relay follows the same flow: **Trigger → Conditions → Actions**. For a full reference of every [trigger, condition, and action](/relays/building-blocks), see the Relay building blocks page.

<Note>
  **Permissions required:** By default, only **Admin** users can access Relays. If you don't see the Relays module, ask your workspace admin to grant you **Relay Management** permissions via **Settings → Team Management**. Learn more: [Team Management](/settings/workspace-settings/team-management).
</Note>

---

## How to create or edit a Relay

### 1. Visit the Relays module

Your first visit to **Relays** opens the **Relay Templates** board. It holds 58 templates in seven outcome groups. Groups and template cards expand and collapse, so you can scan all seven at once and open just the one you need.

Pick a template to start from, or click **Add Relay** to build from scratch. See [Relay templates](/relays/templates#starter-templates-that-ship-today) for every template and what it does.

<Frame>
  ![Relays Module 1](/images/relays-module-1.png "Relays Module 1")
</Frame>

All Relays appear in the **Relays** tab. The list has five columns, left to right: **Name**, **Description**, **Trigger**, **Order**, and **Actions**. The **On/Off** toggle lives in the Actions column, along with the vertical **⋯** menu.

The list **groups Relays by Trigger**, and the side menu sorts those triggers alphabetically. Within a group, MessageDesk sorts by **Order**, so you can scan every Relay on a line or event at a glance. See [Relay building blocks](/relays/building-blocks#triggers) for all 14 triggers.

<Note>
  By default, new Relays are **paused**. Toggle them **On** when you're ready.
</Note>

### 1a. Order your Relays

Within a Trigger group, Relays execute **top-down in Order**. Ordering matters when more than one Relay's conditions match the same event. For example, a keyword auto-reply and a generic after-hours reply that both listen for **Message Received**.

To change the run order, use the **Order** column:

- Click the **up** or **down** arrow on the vertical counter to move a Relay one position, or
- Click the number and **type the exact Order value** you want.

There's no drag-and-drop. The counter is the only way to reorder.

<Note>
  **All matching Relays run.** If multiple Relays in a Trigger group match the same event, every one of them runs in Order. A higher-priority Relay does **not** stop later Relays from evaluating.
</Note>

<Tip>
  Put **narrow, specific** Relays (keyword matches, anonymous-contact capture) **above** broad catch-alls (after-hours auto-reply). The specific behavior runs first, and downstream actions like **Add label** or **Assign** layer on top in the order you expect.
</Tip>

### 2. Name and describe your Relay

Click the vertical **⋯** (three dots) next to a Relay to **Rename**, **Edit description**, or **Delete**.

<Tip>
  Add an emoji (e.g., 💤 for after-hours) so you can scan the Relays list at a glance.
</Tip>

![Relay Name Description Pn](/images/relay-name-description.png)

### 3. Set a **Trigger**

Pick the event that starts the Relay. Fourteen triggers are available. Three of them fire against a contact rather than a conversation: **Contact Created**, **Contact Updated**, and **Inbound Webhook Received**. Conversation-scoped conditions and actions don't apply to those.

See [Relay building blocks](/relays/building-blocks#triggers) for what each trigger fires on and which ones carry restrictions.

<Note>
  Templates include the **Message Received** trigger by default.
</Note>

<Note>
  **Changing the trigger on an existing Relay.** If you switch a Relay's trigger, MessageDesk removes any conditions the new trigger can't support. The app shows a warning with a count before you save (for example, "Changing the trigger will remove 1 incompatible condition from this relay"). MessageDesk also removes any Event Data values used as inputs on existing actions, because those fields don't exist on the new trigger's event. Review your conditions and action inputs after switching triggers.
</Note>

![Relay Message Received Trigger Pn](/images/relay-message-received-trigger.png)

### 4. Add **Conditions**

Conditions control **where and when** a Relay runs. Add as many as you need and combine them with **AND** or **OR**.

Which conditions you see depends on the trigger. Eight are always available, and a few are scoped to a single trigger. See [Relay building blocks](/relays/building-blocks#conditions) for the full list, including the operator selector on **Conversation label equals** and the difference between the three label conditions.

<Tip>
  Turn on **Trigger outside of business hours** on **Active hours** to invert the window. That's how an after-hours reply fires only when you're closed.
</Tip>

![Relay Condition Pn](/images/relay-condition.png)

### 5. Add **Actions**

Actions run when the conditions match. Add one or many, in the order you want them to run. Chain them freely: **Reply**, **Assign**, and **Label** in a single Relay is a common combination.

The **Add Action** menu varies by trigger, so check it for the trigger you picked. See [Relay building blocks](/relays/building-blocks#actions) for every action and which triggers it appears on.

Two things worth knowing while you build:

- **Delays.** Add a **Delay** to **Reply to message** to wait minutes or hours before sending. Delays are how you stop duplicate auto-replies inside a tight back-and-forth.
- **Event Data or Custom Value.** **Send Message**, **Send Comment**, and **Update Contact Property** can pull a value from the triggering event instead of using fixed text. Pick an **Event Data** property, or choose **Custom Value** to type your own. See [Event Data](/relays/building-blocks#event-data).

![Relay Action Pn](/images/relay-action.png)

### 6. Activate your Relay

Use the **toggle** to turn the Relay **On**. You can pause anytime without losing your setup.

![Relay Toggle Pn](/images/relay-toggle.png)

## Managing Relays

### Pause / resume

- From the list: toggle **On/Off**
- From details: use the status toggle at the top

Paused Relays don't evaluate triggers or run actions.

### Delete

Open the Relay → **⋯** → **Delete**.

<Warning>
  Deleting is permanent. If you might reuse the Relay, **pause** instead.
</Warning>

## Relays and conversation status

When a Relay sends an outbound message, MessageDesk updates the conversation's status the same way it would for a teammate's reply. This applies to after-hours auto-replies, out-of-office replies, and any other Relay action that sends a message.

| Event | Resulting status |
| --- | --- |
| Inbound message arrives | **Unread** |
| Relay sends an auto-reply | **Replied** |
| A teammate opens the conversation in the Inbox | **Read** |
| A teammate closes the conversation | **Closed** |

<Note>
  **Auto-replies don't mark a conversation as Read.** A Relay reply moves the conversation out of the **Unread** filter and into **Replied**. The conversation is only marked **Read** when a teammate opens it. After-hours threads still surface for human review the next morning, even though the customer already got an automated acknowledgement.
</Note>

This behavior applies to every Relay action that sends a message: after-hours auto-reply, keyword auto-reply, anonymous-contact first-touch, and so on.

### Force Read or Unread from a Relay

The default status transitions above cover most flows, but two actions let a Relay set the status explicitly:

- **Mark Conversation Unread** puts the conversation back into the **Unread** filter after the Relay runs. Add it to an after-hours auto-reply so the customer's message still queues for morning review instead of sitting in **Replied**. The shipped **After-Hours Auto Reply** template uses this action, and **Keep Keyword Threads Unread** uses it to hold matching keyword threads for review.
- **Mark Conversation Read** marks the conversation **Read** as part of the Relay run. Add it to one-shot acknowledgement or auto-close flows (appointment confirmations, delivery pings) where no human review is needed after the Relay sends its reply.

If you use neither action, the default table above still applies.

## Relays best practices

- **Start simple.** Test one Relay before scaling across teams.
- **Name clearly.** Use descriptive titles like `Teammate 1 - Delegation Relay` or `Region X,Y, Z Autoresponder`.
- **Test with your phone.** Send yourself a message to confirm behavior.
- **Combine with templates.** Use pre-saved templates to standardize replies.
- **Audit regularly.** Disable or update Relays as team structure changes.

## Technical notes and behavior

- **Relay order:** Within a Trigger group, Relays run top-down in the **Order** you set on the Relays list. All matching Relays run. A higher-priority Relay doesn't short-circuit later Relays. Reorder from the **Order** column using the up/down arrows or by typing the numeric value.
- **Action order:** Actions execute top-to-bottom in the order you add them.
- **Delays:** Units include minutes/hours. Use to prevent duplicate “fast follow” replies.
- **Active hours:** Configure daily windows; invert to run only outside business hours.
- **Permissions aware:** Assign/Label actions respect **Roles & Permissions**.
- **Testing tip:** Start with a single condition/action, confirm it fires, then layer on complexity.

## Frequently asked Relay questions

**Do Relays respect roles & permissions?**<br />Yes. Assign/Label actions follow your **Roles & Permissions** settings.

**Can multiple Relays run on one inbound message?**<br />Yes. Every Relay whose conditions match will run, in the **Order** you set. See [Order your Relays](#1a-order-your-relays).

**Can I include media in auto-replies?**<br />Yes. Keep each file **≤ 10 MB** (files **\> 500 KB** are sent as links). See [**Media**](/messaging/media).

**Can I pause without losing my setup?**<br />Yes. Toggle **Off** to pause. Toggle **On** to resume.

**How do I avoid duplicate automated replies?**<br />Add a **Delay** to the **Reply** action, or narrow conditions (e.g., “Is new conversation”).

**Does a Relay auto-reply mark the conversation as Read?**<br />No. It moves to **Replied**, which takes it out of the **Unread** filter. Only a teammate opening it marks it **Read**. See [Relays and conversation status](#relays-and-conversation-status).

**What happens if I change the trigger on an existing Relay?**<br />MessageDesk drops any conditions and Event Data inputs the new trigger can't support, and warns you before you save. See [Set a Trigger](#3-set-a-trigger).

**Can I set up an out-of-office reply for just one person?**<br />Yes, even on a shared line. Add the **Teammate Assigned** condition set to the person who's out. See [Out-of-office for one teammate](/relays/templates#out-of-office-for-one-teammate-even-on-a-shared-line) for the build.

## Troubleshooting

**A Relay didn't fire**

- Confirm it's **On** (not paused).
- Verify the **Trigger** is “Message Received”.
- Temporarily loosen **Conditions** (switch `AND` to `OR`, remove a filter) to test.

**Auto-reply sent multiple times**

- Add a **Delay** to your **Reply** action so back-to-back messages don't both trigger an instant response.

**Assign/Label didn't apply**

- Check the target user/label permissions.
- Remove long **Delays** while testing to see results immediately.

**Unexpected timing**

- Review **Active hours** and the **invert** setting.
- Check your workspace **timezone**.
